# 官方赛题数据说明（ERA5 气象数据）

> 这份文档专讲**赛题最初让你拉取的那套官方数据**：它长什么样、放在哪、每个通道是什么、
> 怎么被读进模型、怎么归一化、怎么拼成 72 通道输入。配合 `config.yaml` / `era5_new.py` /
> `inference.py`（都已加详细中文注释）一起看。

---

## 一、数据是什么

**ERA5** 是欧洲中期天气预报中心（ECMWF）的再分析数据，是气象机器学习的“标准数据集”。
赛题给的是全球 **0.25° 分辨率**的格点数据：

- 空间：纬向 **721** 个点（90°S → 90°N）× 经向 **1440** 个点（0° → 360°），即 `img_size = [721, 1440]`。
- 时间：**6 小时**一个时间步（`time_res = 6`）。一条训练样本 = 用 t 时刻预测 **t+6h**。
- 变量：共 **69 个通道**（见第三节）。

> 赛题约束（`config.yaml` 里标 `AI4S ... 不可更改` 的）：分辨率 721×1440、时间分辨率 6h、
> 推理 batch_size=1、world_size=1，这些改了会报错或判错。

## 二、数据目录结构

`config.yaml` 里三个路径都指向 `../onedatasets/ERA5_test/`：

```
onedatasets/ERA5_test/            ← data_dir（数据根）
├── metadata.json                 ← 变量名清单（69 个，定义了通道顺序）
├── stats/                        ← stats_dir（归一化统计量）
│   ├── global_means.npy          ← 每通道全局均值，形状 [1, C, 1, 1]
│   └── global_stds.npy           ← 每通道全局标准差，形状 [1, C, 1, 1]
├── static/                       ← static_dir（3 个静态场，不随时间变）
│   ├── land_mask.npy             ← 陆海掩码
│   ├── soil_type.npy             ← 土壤类型
│   └── topography.npy            ← 地形高度
├── data/                         ← 逐时间戳真值（result.py 评分时读）
│   └── {年}/                     ← 如 2012/
│       └── {YYYYMMDDHH}.h5       ← 每个时间戳一个文件，内部 "fields" 形状 [C, H, W]
└── data_merged/                  ← 逐年合并（era5_new.py 自包含管线读）
    └── {年}.h5                   ← 一整年，内部 "fields" 形状 [T, C, H, W]
```

**两种 h5 布局，同一份数据的两种组织方式：**
- `data/{年}/{时间戳}.h5`：一个文件 = 一个时刻，`fields` = `[C, H, W]`。评分脚本 `result.py` 用它当真值标签。
- `data_merged/{年}.h5`：一个文件 = 一整年，`fields` = `[T, C, H, W]`，还带属性 `attrs["variables"]`（通道名）和 `attrs["time_step"]`（步长小时数）。`era5_new.py` 用它。

> 打开 h5 的通用方式：`h5py.File(path)["fields"]`。数据主键统一叫 **`fields`**。

## 三、69 个通道是什么（★最该记住）

通道 = **4 个地面变量** + **5 类高空变量 × 13 个气压层** = 4 + 65 = **69**。
顺序在 `config.yaml: channels` 和 `metadata.json: variables` 里，**两者必须完全一致**。

**前 4 个（地面 surface）：**
1. `mean_sea_level_pressure` 海平面气压（msl）
2. `10m_u_component_of_wind` 10 米 U 向风（u10）
3. `10m_v_component_of_wind` 10 米 V 向风（v10）
4. `2m_temperature` 2 米气温（t2m）

**后 65 个（高空 upper-air），5 类各 13 层：**
- `geopotential_*` 位势高度 Z（13 层）
- `specific_humidity_*` 比湿 Q（13 层）
- `temperature_*` 温度 T（13 层）
- `u_component_of_wind_*` U 向风（13 层）
- `v_component_of_wind_*` V 向风（13 层）

**13 个气压层（hPa，从低空到高空）：**
`1000, 925, 850, 700, 600, 500, 400, 300, 250, 200, 150, 100, 50`

所以第 5 个通道是 `geopotential_1000`，第 17 个是 `geopotential_50`，第 18 个是 `specific_humidity_1000`……以此类推。

## 四、归一化（模型只看标准化后的值）

`stats/global_means.npy` 和 `global_stds.npy` 形状都是 `[1, C, 1, 1]`（每个通道一个标量，广播到全图）。

- **进模型前**（`era5_new.py` 的 `__getitem__`）：`x = (x - mu) / sd`
- **出模型后**（`inference.py`）：`pred = pred * std + means`，还原成物理量再存盘。
- **评分**（`result.py`）：在**物理量**上算 RMSE/ACC。

> 只取需要的通道：`mu[:, channel_indices, :, :]`。`channel_indices` 是“变量名 → 下标”查出来的。

---

## 五、从 69 通道到 72 通道（模型输入怎么拼）

模型 `Pangu.forward` 期望的输入是 **72 通道**，在 `inference.py` 里现拼：

```
72 通道输入 = [ 4 地面变量 | 3 静态掩码 | 65 高空变量 ]
              invar[:, :4]   surface_mask   invar[:, 4:]
```

- 3 个静态掩码 = `land_mask / soil_type / topography` 堆叠成 `[3, H, W]`（地形还做了标准化）。
- 模型内部再把 `[7:]` 的 65 通道 reshape 成 `(5 变量, 13 层)` 走 3D 分支，`[:7]` 的 7 通道走 2D 分支。

**输出是 69 通道**：地面 4 + 高空 5×13=65。即 3 个静态掩码只进不出。

## 六、metadata.json 的作用

就一件事：给出**全部变量名的权威顺序**。`inference.py: get_stats` 和数据管线都靠它把
`config.yaml: channels` 里要的变量，**按名字**定位到 h5/统计量里的通道下标：

```python
channel_indices = [all_variables.index(v) for v in channels]
```

> ★通道对齐陷阱：本官方基线里 `metadata.json` 正好 = 69 个变量、顺序与 `channels` 一致，
> 所以 `result.py` 里用 `range(len(channels))` 直接取前 69 个也没错。但如果真值 h5 里通道**更多**
> （比如某些数据集是 99 通道），`range(69)` 就会取错通道 → RMSE 爆炸。稳妥写法永远是**按变量名取**
> （我们复现时的 `result_fixed.py` 就是把这里改成按名字对齐）。

## 七、一条样本长什么样（era5_new.py 的 `__getitem__` 返回）

```
invar       [C, H, W]        输入帧（已归一化），C=69
outvar      [C, H, W]        目标帧（t+6h，已归一化）
cos_zenith  [H, W]           太阳天顶角余弦（物理先验：昼夜/太阳高度）
step_idx    int              该年内的起始帧号
time_index  [str, ...]       各帧时间戳 "YYYYMMDDHH"，给输出文件命名
```

## 八、和评分的关系（一句话串起来）

`train.py` 训练 → `inference.py` 对测试集逐样本 `model()` 出预测、存 `result/output/{时间戳}.npy`，
并把每次 `model()` 耗时写 `result/time_record.json` → `result.py` 把预测和真值逐通道比，算 RMSE + ACC。

- **推理时长 V** ← `time_record.json`（只计时 `model()` 那一行，见 `inference.py` 的 AI4S 计时区）。
- **预测性能 W** ← `result.py` 的每通道 RMSE / ACC 平均。
- **轻量化 U** ← 模型大小 + 显存（本数据文档不涉及，见项目其他材料）。
