L9量化与显存:fp16/INT8 + 空间分块

1攻 U 的两条线:模型大小 + 推理显存

U = 模型大小项(20)+ 推理显存项(20),两条独立的线。这一课分别攻:量化攻模型大小(权重存得小),空间分块攻推理显存(跑起来占得少)。两者都要求数值等价、不掉 W——是纯赚的免费分。

先记住一个反直觉的分工

"模型大小"和"推理显存"是两回事。模型大小 = 权重文件多大(靠量化压);推理显存 = 跑一次占多少显存(主要是激活,不是权重)。搞混这两个,就会犯"用权重量化去省显存"的错——对这个任务几乎没用。

2权重量化:fp16 vs INT8(攻模型大小)

模型大小项就是"权重文件相对教师小多少"。学生权重从 fp32 往下压:

fp16 半精度存储(本提交采用)大小 −40%

是什么:把权重从 fp32(32 位)转成 fp16(16 位 = 1 符号 + 5 指数 + 10 尾数)存盘,state_dict 只留模型权重 + cfg(去掉优化器状态等冗余)。文件从 17.47MB → 10.46MB。

为什么数值等价、零风险:推理本来就走 autocast fp16——权重不管存 fp32 还是 fp16,前向都会转成 fp16 去算。所以直接存 fp16,和"存 fp32 再转 fp16"数值上几乎一样(实测 maxdiff≈0.008,远小于评测容差,官方 W 完全一致)。加载即用、不需要任何反量化环节,是最稳的压缩。

为什么不追求更省:模型大小项 = (1 − 10.46/1868)×20 已拿到 99.4% 满分,fp16 就够了,再压边际收益极小。

INT8 对称量化(可选,本提交未用)大小 −70%

是什么:每列(通道)取一个缩放 s = max|Wcol| / 127,把权重量化成 int8:Wq = round(W/s),用时反量化 W ≈ s·Wq。文件可压到 5.33MB。

为什么没用它:①大小项已近满,10.46→5.33 只多零点几分;②int8 要么每次用权重时反量化、要么走 int8 GEMM,多一层复杂度和精度风险;③fp16 已经零风险拿满。综合下来 ROI 太低,稳健起见用 fp16。

为什么 INT8 > FP8:同样 8 位,int8 是定点、把整个动态范围均匀切成 256 档;fp8 是浮点、尾数只 2–3 位。对权重这种分布集中的量,均匀定点的 int8 精度更高。

关键对比:注意这里的结论是"对气象这个任务不值得"——因为瓶颈是激活不是权重(见 §3、§4)。换到 LLM decode(权重访存瓶颈),同一个 int8 就是决胜手。方法一样,值不值取决于瓶颈。

3关键判断:显存为什么不靠权重量化

很多人会想:"权重量化不也能省显存吗?"——对这个任务,几乎不能。因为推理显存里,权重只占九牛一毛。

结论:显存靠"管理激活",不靠"压权重"

推理显存的主战场是激活——那些逐层产生、用完却没及时释放的中间张量。所以省显存的正解是空间分块 + 及时释放(第 5 节),把激活的峰值压下来。权重量化对显存这条线基本无效,它只帮"模型大小"那条线。

数学原理 · INT8 对称量化 + "先判哪面墙"

对称量化:用一个缩放 s 把浮点权重压进 [−127, 127] 的 int8:

s = max|W| / 127　,　Wq = round(W/s)　,　W ≈ s·Wq(round 误差 ≤ s/2)

分组量化:每 g 个元素单独一个 s,g 越小越能抗 outlier(group16 比 group64 精度好)。这就是 Qwen int8 的关键。

但用不用,先判瓶颈:量化只在"权重是瓶颈"时有用。显存/访存 ≈ 激活 + 权重,气象场推理里激活 ≫ 权重(99% vs 1%),所以量化权重对显存无效;LLM decode 反复读权重,量化权重减半 HBM 读才有效。同一把量化锤子,得先看准是哪颗钉子。

参考项目 · LLM.int8(Dettmers 2022)/ SmoothQuant(Xiao 2022)/ 梯度检查点(Chen 2016)
抽象问题低比特量化的难点是outlier:LLM.int8 让 outlier 通道保 fp16、其余走 int8;SmoothQuant 把激活的量化难度"迁移"到权重(逐通道缩放);梯度检查点则用重算换显存(反传时重算激活而非全存)。
怎么变好让百亿级 LLM 能 int8 推理、低显存训练,是大模型落地的关键工具。
桥接到我们我们的 int8/fp16 权重量化与它们同源(对称量化 + 分组 + outlier 处理)。更关键的迁移是方法论:先用 roofline 判"权重墙还是激活墙",再决定量化什么——Qwen 撞权重墙(量化大赚)、气象撞激活墙(量化无用,靠 tiling)。而梯度检查点"重算换显存"和我们 tiling"分块换显存"是同一思想——都是拿计算换激活显存。

4对比 Qwen:同是 INT8,两种命运

同样是 INT8 权重量化,在气象和大语言模型 Qwen 上一个没用、一个是决胜手——原因就在"瓶颈是激活还是权重":

气象:INT8 权重量化 → 没用

场到场推理,激活占显存 99%、也是访存大头。权重才 10MB,量化它对显存/速度都杯水车薪。所以气象不用 INT8,只用 fp16,显存靠 tiling。

Qwen:INT8 权重量化 → 决胜手

单流 decode 是访存瓶颈——权重要反复从 HBM 读。INT8 把权重体积砍半 = HBM 读量砍半 = decode 直接快。所以 Qwen 的 89 分核心就是 INT8 权重量化 + 手写 int8 GEMV 核。

一条通用的判断准则

先搞清瓶颈是"权重"还是"激活",再决定量化什么。权重是瓶颈(如 LLM decode 反复读权重)→ 量化权重(INT8/W8A16)大赚;激活是瓶颈(如高分辨率场推理)→ 量化权重没用,要去管理激活。同一把 INT8 锤子,得先看准是不是那颗钉子。

5显存正解:空间分块 tiling(923 → 548MB)

既然显存大头是激活,尤其是 stem/head 那两层高分辨率卷积(在 721×1440 全分辨率上算)的中间张量,正解就是:沿空间维度切块处理、用完即释放。

# 空间分块 + 及时释放(数学等价,峰值 923→548MB) for strip in 沿纬度切块(x): # 非重叠条带,stride=kernel → bit-exact out_strip = conv(strip); 收集(out_strip); del strip x.untyped_storage().resize_(0) # stem 后立即释放最大常驻的输入张量 # 编/解码器每个 block 的中间张量也用完即 del

6另两招:SDPA off + fp16 输入 + 流式

tiling 之外,还有几招也在管理激活/常驻张量,叠加起来把峰值再往下压:

SDPA off−199MB

本 DCU 的融合注意力(scaled_dot_product_attention)回退实现会分配巨大工作集(~579MB)。而窗口内 token 很小(144),关掉 SDPA 用朴素注意力反而省 ~199MB 且更快。这是"高级算子不一定更省"的典型。

fp16 输入构造−299MB

直接以 fp16 构造输入,避免 fp32 输入张量常驻(约 299MB)。与 autocast 内部转换 bit-exact(stem maxdiff=0),纯赚。

FAST_STREAM 流式(566 档)

更进一步:输入留 CPU 逐条 H2D、输出逐条 D2H 到 pinned buffer,GPU 上不驻留整块输入/输出,峰值降到 ~566MB。连续布局满 DMA,速度也快。

7Conv→GEMM 快赢(顺带省 V)

顺手一招,主要省 V(时长):stem/head 的 patch 卷积是非重叠的(stride=kernel),数学上严格等价于 unfold(im2col)+ 矩阵乘。改走 hipBLAS GEMM,就能绕开 MIOpen 卷积核对新形状的 JIT 编译(首样本约 5 秒):

# 非重叠 patch conv ≡ unfold + linear(GEMM),避 MIOpen JIT 编译 ~5s Wf = W.reshape(O, V*kz*kh*kw).t() # 卷积核摊平成矩阵 o = blk_unfold @ Wf + b # 走 hipBLAS GEMM(fp32 累加保真) # 与原卷积 bit-exact,但省掉首样本 conv 编译的 ~5s 冷启动

(这招同时服务 U 和 V:分块保持显存优化、GEMM 化省首样本时间。评测按同步口径计时,首样本的 5s 冷启动省掉很值。)

8HIP/DCU 视角 + 本课要点

这些优化在国产 DCU 上的意义

海光 DCU 的融合注意力回退、MIOpen 卷积 JIT 都可能"帮倒忙"(工作集大、首样本慢)——所以要用 hy-smi 实测显存、rocprof 看算子,别默认"官方算子就是最优"。SDPA off、Conv→GEMM、tiling 这几招正是针对 DCU 实测出的坑对症下药。方法论:一切以实测峰值/时长为准,数学等价的省法优先。

本课要点(记住这 6 条)
  1. U 两条线:模型大小(靠量化)+ 推理显存(靠管理激活),别搞混。全是数学等价的免费分。
  2. 权重量化:fp16(17.47→10.46,数值等价即用,本提交);INT8(→5.33,需反量化、ROI 低,未用)。大小项已近满。
  3. 关键判断:推理显存激活占 99%、权重占 1%,所以显存靠 tiling 不靠权重量化。
  4. 对比 Qwen:同是 INT8,气象没用(激活瓶颈)、Qwen 决胜(decode 权重访存瓶颈)。先看准瓶颈是权重还是激活。
  5. 显存正解:空间分块 tiling(非重叠 stride=kernel → bit-exact)+ 及时释放,923→548;再加 SDPA off(−199)、fp16 输入(−299)、流式(566)。
  6. Conv→GEMM:非重叠 patch 卷积等价 GEMM,避 MIOpen JIT 首样本 5s。全程 hy-smi/rocprof 实测为准。
