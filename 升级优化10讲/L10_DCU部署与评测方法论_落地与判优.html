1最后一公里:落地与判优

模型练得再好,部署跑不快、评测判不准,分照样拿不到。这一课两件事:①用手写 HIP 核把推理压到极致(拿满 V);②用正确的计时口径和判优方法,把每一分都兑现、不误判。

关键心法:不迷信框架默认算子。海光 DCU 的融合注意力回退、卷积 JIT 都可能帮倒忙(见 L9)。真正压榨性能,要理解算子背后的数学结构,亲手写更贴硬件的核。下面两节把 flash 和 GEMM 的数学原理讲透——你会发现它们解决的抽象问题,和我们的问题是同一个。

2手写 flash 注意力核:数学原理 + 参考

注意力的定义是 O = softmax(QKᵀ/√d)·V。朴素实现要先算出完整的 N×N 分数矩阵 S=QKᵀ,再 softmax,再乘 V——把 N×N 物化到显存是万恶之源(N 大时显存爆、访存慢)。

数学原理 · 在线 softmax(online / streaming softmax)

softmax 的稳定写法要减去最大值防溢出:softmax(x)ᵢ = e^(xᵢ−m) / Σⱼ e^(xⱼ−m),其中 m=max(x)。

关键:这个和可以增量地算。把 K、V 分成小块逐块处理,维护两个"跑动统计量"——当前最大值 m 和当前指数和 ℓ。每来一个新块,若出现更大的最大值,就用缩放因子把已累积的结果重标定:

m′ = max(m, mblk),　ℓ′ = ℓ·e^(m−m′) + ℓblk·e^(mblk−m′),　O′ = O·e^(m−m′) + PblkVblk

于是永远不用把 N×N 的 S 存下来:一块算完即弃,显存从 O(N²) 降到 O(N),还因为数据一直在片上高速缓存里流动而更快。

参考项目 · FlashAttention(Dao et al., 2022 / FlashAttention-2, 2023)
它做了啥把注意力做成 IO 感知(IO-aware)的分块在线 softmax 核,不物化 N×N 分数矩阵,只在片上 SRAM 里分块累加。
它怎么变好让长上下文训练/推理变得可行:显存 O(N²)→O(N)、速度 2–4×,几乎无损。是当今所有大模型注意力的标配。
抽象桥接它解决的抽象问题是"softmax(QKᵀ)V 如何不物化中间大矩阵"。我们的窗口注意力虽然窗口小(144 token),数学结构完全一样——同是 softmax(QKᵀ)V。所以把 flash 的在线 softmax 思想搬进手写 HIP 核,同样能省激活、提速(实测窗口注意力核约 2.14ms,比 DCU 的 SDPA 回退快约 2×、显存降约 200MB)。
# 手写 HIP flash 核(QK-Norm+温度+bias+softmax+PV 一体,不物化 N×N) for kv_block in K,V 的分块: S = (q_norm @ k_block.T) * tau + bias # 小块分数(不落显存) m_new = max(m, S.max()); scale = exp(m - m_new) O = O*scale + exp(S - m_new) @ v_block # 在线累加 + 重标定 l = l*scale + exp(S - m_new).sum(); m = m_new O = O / l # 最后一次归一

3手写 GEMM 核 + roofline:数学原理 + 参考

神经网络里几乎所有算力都归约成矩阵乘(GEMM):Linear 是 GEMM、注意力的 QKᵀ 和 PV 是 GEMM、卷积也能化成 GEMM(L9)。把 GEMM 写快,就把整个模型写快了。

数学原理 · 分块矩阵乘 + Roofline 上界

C = A·B,C[i,j]=ΣkA[i,k]B[k,j]。硬件按 16×16×16 的小块做"乘加(MMA)"——一条 v_mmac 指令算一个 16×16×16 的块并累加到 fp32。整个 C 就是无数这样的小块拼起来。

快不快由 Roofline 决定:性能 = min(峰值算力, 算术强度 × 带宽)。算术强度 = 计算量 / 访存量 = FLOPs / bytes。

算术强度 I = 2·M·N·K / ( (MK+KN+MN)·字节 )　→　I 越高越"计算密集",越能吃满 Matrix Core

GEMM 的算术强度高(复用多),是计算受限的——正好适合用 Matrix Core 榨满算力。而 decode 的 GEMV(矩阵×向量)算术强度低、是访存受限的——这就是 L9 里 Qwen 要靠 INT8 减访存的数学根源。

参考项目 · CUTLASS / rocBLAS·hipBLASLt + Roofline 模型(Williams 2009)
它做了啥CUTLASS(NVIDIA)/ rocBLAS(AMD·海光)是分块 GEMM 模板库,用 Tensor/Matrix Core 的 MMA 指令 + 多级 tiling(寄存器/共享内存/全局)榨满算力;Roofline 模型给出"算力 vs 带宽"的性能上界。
它怎么变好手写/模板化的 tiled GEMM 比朴素三重循环快几十倍,是所有深度学习框架的算力底座。
抽象桥接抽象问题是"如何按硬件层级分块、最大化数据复用、逼近 roofline 上界"。我们的每个 Linear/注意力都是 GEMM,同一套分块数学直接适用。所以手写 HIP GEMM 核(per-shape 选 tile:M≤512→32×32、N≥1536→128×256)在 DCU 上比通用库快约 1.9–2.3×,还省掉 rocBLAS 的 155MiB 常驻和首样本 JIT。

4CUDA → HIP 完整对照(方法论硬件无关)

所有优化方法论在 NVIDIA 和海光 DCU 上完全一致,只换工具名。一张对照表带走:

nvidia-smi→hy-smi看显存 / 利用率
ncu / Nsight→rocprof / omniperf看算子耗时 / 瓶颈
warp(32 线程)→wave64(64 线程)SIMD 执行单位
Tensor Core→Matrix Core(v_mmac)矩阵乘加硬件
cuBLAS / CUTLASS→rocBLAS / hipBLASLtGEMM 库
.cu / nvcc→.hip / hipcc(gfx936)源码 / 编译器
迁移经验

CUDA 代码大多能用 hipify 自动转,但性能调优要重来:wave64(而非 warp32)、Matrix Core 的 tile 形状、LDS(共享内存)bank 冲突,都要按 gfx936 重新调。算法/数学不变,只有硬件常数变——这正是"理解数学结构"比"背某张卡的 API"更值钱的地方。

5正确计时:为什么必须 synchronize

数学原理 · 异步执行模型(asynchronous kernel launch)

GPU/DCU 的 kernel 是异步发射的:CPU 发出 model(x) 后立刻返回,kernel 还在 GPU 上排队执行。若此时就记 end_time,量到的是"发射时间"而非"执行时间"——严重低估真实耗时(实测偏差可达 100ms+)。

修法:在 model(x) 后、end_time 前插一个 torch.cuda.synchronize(),阻塞 CPU 直到 GPU 全部算完,量到的才是真实同步耗时,与官方评测口径一致。

start = time() out = model(invar) torch.cuda.synchronize() # ★ 等 DCU 真正算完,否则量到的是"发射时间" end = time() # V(推理时长)按此同步口径计,才和判卷一致
合规提醒

计时区代码是赛题标注"不可更改"的部分,只能在规定位置加 synchronize。V 分对时长很敏感,计时口径错了会直接失分或被判违规。这是部署阶段的基本功,也是"落地"的一部分。

6评测口径:15 指标 vs 69 通道

W(精度)的算法是逐通道打分再平均。每个通道:min((教师RMSE/学生RMSE)², 1) + min((学生ACC/教师ACC)², 1)(RMSE 项 + ACC 项,各满分 1)。区别只在对哪些通道求平均:

69 通道口径(官方判卷)

对全部 4 地表 + 5×13 高空 = 69 个通道求均值。高空场(z/t/q/u/v)拟合好,拉高均值。这是判卷用的真实口径。

15 指标口径(诊断)

只看官方钦定的 15 个关键指标(近地面 4 + 高空 11)。含 4 个近地面项(学生短板),均值偏低。用来照短板,不是判卷分。

为什么两个口径差这么多

算术平均对取哪些项极敏感。15 指标里近地面占 4/15(权重大),把均值拉低;69 通道里近地面只占 4/69(被大量拟合好的高空稀释),均值高。看分/判优必须认清口径——同一个模型,15 指标口径和 69 通道口径能差 2 分以上(这正是 L1 里"起点 94、终点 96"要澄清的口径问题)。

7scorecard 判优:别只看 RMSE

选哪个模型上,不能只看一个 RMSE。scorecard(记分卡)把 U/V/W 三维 + 逐通道 + 合规一起摆出来看,避免"赢了一项、输了总分"。

一张 scorecard 至少要看:
  • U/V/W 三维分别是多少 —— 别为了 W 涨 0.5 把 V 掉 1(L1 的三维账)
  • 逐通道 RMSE/ACC —— 看清是哪些通道涨、哪些跌(攻 W 每招都双刃,L6)
  • 对真值 vs 对教师 —— 判优主看对真值,别被 val_match 误导(L5)
  • 合规项 —— 计时口径、是否改了不可动的代码、量化是否持久化违规
  • 最终以判卷为准 —— 训练机/离线指标只作参考,别当结论
判优心法(贯穿全课)

一个总分背后是一堆此消彼长的账:U↔W(更准的权重更大)、V↔W(更准的推理更慢)、近地面↔高空(真值监督的双刃)。scorecard 就是把这些账一次性摊开,让你在"净分最高"而不是"单项最好"的方向上迭代。这是把 94 顶到 96 的方法论保障。

8收官总账 96.12 + 全课回顾

L10 要点 + 全课一句话回顾
  1. flash 核:在线 softmax 增量累加,不物化 N×N,显存 O(N²)→O(N)。源自 FlashAttention,我们窗口注意力同结构可直接借。
  2. GEMM 核 + roofline:一切归约到分块矩阵乘;算术强度决定撞带宽墙还是算力墙,先判墙再选优化。手写 tile 比通用库快 1.9–2.3×。
  3. CUDA→HIP:算法/数学不变,只换工具(hy-smi/rocprof/wave64/Matrix Core/rocBLAS);理解数学结构 > 背 API。
  4. synchronize:异步执行必须同步后计时,否则低估耗时、失分或违规。
  5. 口径与判优:判卷用 69 通道;scorecard 综合 U/V/W + 逐通道 + 合规,以判卷为准,别只看一个 RMSE。
  6. 全课:U/V 靠轻量骨架+组件+减脂+部署拿满,W 靠蒸馏+真值+物理破天花板;数学上,每个优化都对应一个可迁移的抽象问题(避免物化、分块复用、在线累加、低秩、硬约束…)。
