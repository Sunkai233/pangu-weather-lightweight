真实共享数据 · 内存优化蒸馏训练实测

先导杯气象大模型轻量化(决赛 · 海光 DCU)——用集群共享盘的真实 ERA5,在容器内存受限下训练学生模型

环境:SCNet 海光 DCU 容器 · torch 2.5.1 · onescience · 教师 Pangu(model_bak.pth) · 学生 MaxVit3DStudent

一句话。共享盘 /work2/share/.../ERA5/old-data 有 21 年 × 每年 1460 时刻 ≈ 3 万个真实时刻(99 通道,单文件 411MB)。但它不在容器挂载里,且容器内存被 cgroup 限死在 63.8 GB——直接把几百样本的教师输出塞进 RAM 会 OOM。本文记录如何 ① 把共享数据读进容器、② 用落盘缓存绕开内存墙,在几百个真实样本上完成学生蒸馏训练。

一　共享数据:在哪、长什么样、怎么读进容器

1.1 共享盘的真实规模

登录/计算节点的宿主机上,共享盘路径 /work2/share/sugonhpcapp01/ERA5/old-data:

项值
年份1980–2000,共 21 年
每年时刻数1460(6h 一个,4×365)
总时刻≈ 30,660 个(几万,远超"几百/几千")
单文件data/{年}/{YYYYMMDDHH}.h5,99 通道 (99,721,1440),411 MB/个
一年占用≈ 560 GB

1.2 关键难点:共享盘不在容器里

DCU 训练跑在 sudo ai_docker exec 进的容器里,但容器的挂载命名空间看不到 /work2(ls /work2 → No such file)。容器里 /public/share/sugonhpcapp01 是空挂载点。只有计算节点宿主机能读 /work2。而容器和宿主机共享同一个 /public/home NFS。

读法(与当年 era5_real 同一套路,它带 .copy_done 标记):在宿主机上把需要的年份/时刻从 /work2 拷到 /public/home/.../era5_big(容器可见),容器再从 /public 读。stats/static/metadata 直接复用 era5_real 的(同变量、同归一化)。

1.3 实测

宿主机 cp 速度实测 ~550 MB/s(20 个文件 7.7GB / 14s)。本次拷训练年 1980 的 300 个时刻(115GB)+ 验证年 1981 的 40 个,共 131GB。容器里 ERA5Datapipe 读到:train 1980 = 299 个可用样本、val 1981 = 39 个,自动把 99 通道按 metadata.json 过滤成模型用的 69 通道。

二　内存的坑与优化:从 RAM 缓存到落盘缓存

2.1 坑:容器内存被限死 63.8 GB

原始的"快速版"训练脚本 distill_scnet_fast.py 为了加速,把所有样本的 (输入 + 教师输出 + 真值) 一次性缓存进 RAM,训练循环不再跑教师、不再读 NFS。它的注释说"节点 461G RAM"——但那是宿主机。容器 cat /sys/fs/cgroup/memory/memory.limit_in_bytes = 63.75 GB。

每个样本 RAM 缓存需存 5 个 fp16 大张量:输入72 + 教师sf4 + 教师ua65 + 真值sf4 + 真值ua65 = 210 通道:

每样本 ≈ 210 × 721 × 1440 × 2 字节 ≈ 436 MB
63.8 GB / 436 MB ≈ 146 个样本  ← RAM 缓存上限
→ 299 个样本 × 436 MB ≈ 147 GB  ≫ 63.8 GB  ⇒ 进程被 OOM Killed
实测复现:直接跑 299 样本,进程在缓存阶段被 Killed(SIGKILL,无 traceback)。这正是"决赛强化轻量化/内存约束"要解决的真问题。

2.2 优化:落盘缓存(disk cache)

解法 = 教师输出预计算落盘,训练用 DataLoader 按需从磁盘读,RAM 只占少量。再叠两个省盘技巧:

  • 只存动态 69 通道,不存 3 个静态掩码(常量,训练时再插回)→ 输入从 72 压到 69。
  • 纯蒸馏(对教师),训练样本不存真值 → 每样本只存 输入69 + 教师69 = 138 通道 ≈ 287 MB(省掉一半)。
  • 验证集(39 个)留 RAM 且带真值,用于算 val_gtL1(对真值)与 val_match(对教师)。
训练缓存(磁盘) = 250 × 287 MB ≈ 72 GB     (家目录配额 450G 内,够)
验证缓存(RAM)  = 39 × 436 MB ≈ 17 GB      (< 63.8 GB,够)
训练时 RAM 峰值 ≈ DataLoader预取(3 worker × 287MB) + 验证17G + 模型 ≈ 20 GB  ✓
要点:RAM 缓存快但受 63.8G 顶;落盘缓存慢一点(每 epoch 多读磁盘)但能吃下几百/几千样本——内存不再是上限,磁盘才是。要扩到几千,继续拷更多年份、缓存到磁盘即可。

三　训练流程与关键代码

完整脚本见同目录 代码/distill_diskcache_scnet.py。三段式:

3.1 落盘缓存(教师只跑一次)

# 每个训练样本:读 era5_big → 拼 72ch → 教师前向(bf16) → 只存 输入69+教师69 到磁盘
with torch.no_grad():
    for i, data in enumerate(train_loader):
        x, x69 = build72(data[0])              # x:72ch(带掩码)  x69:69ch(存盘)
        with torch.autocast("cuda", dtype=torch.bfloat16):
            ts, tu = teacher(x)                # 教师输出(蒸馏目标)
        torch.save({"x69": x69[0].half().cpu(),
                    "tsf": ts[0].half().cpu(),
                    "tua": tu[0].half().cpu()}, f"tcache/tr_{i:04d}.pt")

3.2 按需读盘的 Dataset + 静态掩码插回

class DiskCache(Dataset):
    def __getitem__(self, i):
        d = torch.load(self.paths[i], map_location="cpu")
        return d["x69"], d["tsf"], d["tua"]        # 低内存:一次只读一个样本

def ins_mask(x69):                                  # 训练时把 3 个常量静态掩码插回
    return torch.cat([x69[:, :4], smask, x69[:, 4:]], 1)   # 69 → 72

3.3 学生训练(AdamW + warmup余弦 + 梯度裁剪 + EMA + bf16)

loader = DataLoader(DiskCache(paths), batch_size=1, shuffle=True,
                    num_workers=3, pin_memory=True, prefetch_factor=2)   # 预取重叠 IO
for ep in range(epochs):
    for x69, tsf, tua in loader:
        x = ins_mask(x69.float().to(DEV))
        with torch.autocast("cuda", dtype=torch.bfloat16):
            ss, su = student(x); su = su.reshape(tua.shape)
        loss = wl1(ss, tsf, sw, 0.25) + wl1(su, tua, pw, 1.0)   # 加权 L1 蒸馏(地面0.25/高空1.0)
        loss.backward(); clip_grad_norm_(...); opt.step(); ema_update(ema, student)
    val_gtL1, val_match = evaluate(ema)            # 对真值 + 对教师 双指标

损失:逐通道加权 L1,权重来自官方 config(海平面气压1.5、2m气温3.0、位势3.0、比湿0.6…)。双指标:val_gtL1 对真实 6h 后场(越低越接近真实技能)、val_match 对教师(表达力,越高越像教师)。

四　实测结果

结论先行:落盘缓存在 63.8G 容器内成功吃下 250 个真实共享样本,学生 8 epoch 干净收敛——train loss 0.35→0.14、val_gtL1 1.20→0.35、val_match(像教师程度)7%→70.7%,全程 RAM 未爆(RAM 缓存版同样样本需 147GB → OOM)。

五　如何扩到几千样本

  • 数据:宿主机继续从 /work2 拷更多年份(1980–2000 任选)到 era5_big/data/{年},config 的 train_ratio 加年份即可。
  • 内存:落盘缓存下,RAM 恒定(只读一个样本),样本数只受磁盘配额限制(每样本 ~287MB,450G 配额可存 ~1500 个)。要更多则清理原始 h5(缓存已含所需),或缩通道/降精度。
  • 速度:每 epoch 从 NFS 读整份缓存是瓶颈;可加大 num_workers、或把缓存放更快的本地盘(若容器有 /tmp 本地存储)。
