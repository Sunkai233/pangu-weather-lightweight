评测打分逐代码:对真值算 W、判优、避坑
score15_fp32.py · 官方 15 指标 W15/W69 · RMSE + ACC · 超 bo3b 才算数

前三课每个改动(快了、省了、准了)到底算不算数,全靠这把尺子量。这一课打开 score15_fp32.py:W 怎么算(RMSE 项 + ACC 项)、怎么对真值 ERA5 评、W15 和 W69 啥区别、权重 remap 这个部署大坑怎么填、为什么用 fp32 口径判优最准、怎么和 bo3b 基线比。全程白底深字、可打印。

怎么读:第 1 章(公式)和第 5 章(remap 坑)最关键。公式让你看懂"提升 W 该往哪使劲";remap 是"训练命名 ≠ 部署命名"的隐形杀手,不填会静默掉分。代码框对应 最优项目代码/04_评测/。

读导读:评测不加分,但决定一切加分算不算↑

L1 让它快(V)、L2 让它省(U)、L3 让它准(W)。但"准没准"得有一把和官方一致的尺子来量——否则你以为涨了,提交才发现没涨甚至跌了。score15_fp32.py 就是这把尺子:在本地用官方口径(对真值 ERA5、15 指标、RMSE+ACC)给学生打 W 分,和 bo3b 基线比,判断这次改动该不该留。

一句话抓住这一课

W 打分 = 把学生和教师在 15 个气象指标上比 RMSE 和 ACC,每项封顶 1 分(min(比值, 1)),加起来 ×20 = 满分 40。评测的两个隐形坑:① 用 fp32 跑(bo3b 在 fp16 会 NaN);② 训练命名要 remap 成部署命名,否则权重静默加载错。这一课把这两个坑讲透。

分W 在总分里的位置 + 三个 score15↑

当前最优 96.1213 = U 38.4288 + V 18.9244 + W 38.4387。本课就是把 W 38.4387(满分 40)这个数算出来、并用它判优。三个评测脚本口径不同,先认清:

脚本口径什么时候用
score15_fp32.py纯 fp32 forward,era5_real/2000判优最准(bo3b fp16 会 NaN,fp32 finite);选权重就看它
score15_dcu.pyCppRunner fast_forward + matrix-core libgemm(fp16)最接近真实评测环境;确认部署链路没掉分
score15_diff.py逐通道对比 W1 vs bo3b vs 教师诊断:哪些通道涨/跌,指导 L3 下一步往哪补

本课主讲 fp32 版(判优口径);8 节会对比另外两个。

1W 打分公式(看懂它就知道往哪使劲)↑

这段干啥:一行算出 W。每个指标两部分:RMSE 项 min((教师RMSE/学生RMSE)², 1)、ACC 项 min((学生ACC/教师ACC)², 1)。两部分各封顶 1(学生再好也不超教师对应项),相加 ≤ 2,对所有指标取平均再 ×20 → 满分 40。

score15_fp32.py · L87
def W(ix):
    return float(np.mean(
        np.minimum((t_rmse[ix]/sr[ix])**2, 1)      # RMSE 项:学生越准(sr 小)越接近 1
      + np.minimum((sa[ix]/t_acc[ix])**2, 1)    # ACC 项:学生越高(sa 大)越接近 1
    ) * 20)
# t_rmse/t_acc=教师, sr/sa=学生; ix=要算哪些通道(15指标 or 全69)
公式告诉你的提分策略
  • 已封顶(min=1)的通道,再优化白费 —— 学生已追平/超教师的指标(比值≥1),分已满,别在它身上花训练预算。
  • 没封顶的通道才是提分点 —— 这正是 L3 真值监督专挑"温度 + 低层 u/v/q"补的原因(它们是没满分的拖后腿项)。
  • RMSE 项对"准"敏感、ACC 项对"形态相关"敏感,两个一起看。

2evalm:对真值算 RMSE + ACC(逐通道)↑

这段干啥:跑一遍测试集,对每个样本:拼输入 → 模型出 ss/su → 反归一化成物理量 pp → 和真值 gt(反归一化的 outvar)比。RMSE = 逐通道 sqrt(mean((gt−pp)²));ACC(异常相关)= 各自减气候态 clim 后的相关系数。

score15_fp32.py · L28–L39
def evalm(model):
  for data in dp.test_dataloader():
    invar, outvar = data[0], data[1]
    x = torch.cat([invar[:,:4], masks, invar[:,4:]], 1)        # 4地面 + 3静态掩膜 + 65高空 = 72
    ss, su = model(x); su = su.reshape(1,65,...)
    pp = (torch.cat([ss,su],1)*sd_t + mu_t)[0].cpu().numpy()   # 预测,反归一化
    gt = (outvar*sd_t + mu_t)[0].cpu().numpy()              # ★真值(t+6h),反归一化
    rmse += np.sqrt(((gt-pp)**2).mean(axis=(1,2)))            # 逐通道 RMSE
    pa = pp-clim; la = gt-clim                              # 减气候态 → 异常
    num += (pa*la).sum(...); p2 += (pa**2).sum(...); l2 += (la**2).sum(...)
  return rmse/n, num/(np.sqrt(p2*l2)+1e-8), n             # (RMSE, ACC, 样本数)
和 L3 的呼应

注意 gt 用的是 真值 outvar,不是教师输出。这正是 L3 "选优对真值"的口径——训练时怎么判优、评测时就怎么打分,两边口径必须一致,改动才可信。

3W15 vs W69 + 官方 15 指标↑

这段干啥:官方只评 15 个指标(OFFICIAL15),sel 是它们在 69 通道里的下标。W(sel)=W15(真实提交口径),W(range(69))=W69(全通道,参考)。

OFFICIAL15 = ["mean_sea_level_pressure","10m_u...","10m_v...","2m_temperature",
  "geopotential_850/700/500","specific_humidity_850/700/500",
  "temperature_850/700/500","u_..._500","v_..._500"]   # 共15

为什么 W15 通常比 W69 略低

15 指标里含 4 个近地面变量(msl/10m_u/10m_v/2m_t),正是学生退化最多的(各约 1.17–1.19×),拉低均值;而 69 通道里大量高层 z/t/q 学生拟合好(拉高均值)。官方按 W15 算,所以判优盯 W15。

5★remap_state:权重重映射(部署/评测大坑)↑

这段干啥:训练脚本(distill_truth)和部署模型(MaxVit3DStudent)对同一层的命名不一样——unified-API vs split-API:训练里叫 patchembed2d.proj.weight,部署里叫 patchembed2d.embedder.proj.weight;recovery、Sampler 也类似,还要双填(.recovery 和 .Reconvery 两个名都填),并丢掉守恒层 conserv.*。不 remap 的后果:load_state_dict(strict=False) 会静默跳过对不上的键 → 那些层用随机初始化 → W 暴跌但不报错。

score15_fp32.py · L54–L83(节选)
def remap_state(sdk, msd):
    if "patchembed2d.embedder.proj.weight" in sdk: return sdk   # 已是部署命名,原样
    out = dict(sdk)
    # embed: proj → embedder.proj(2d 补 kz 维)
    out["patchembed2d.embedder.proj.weight"] = out.pop("patchembed2d.proj.weight").reshape(...)
    # recovery: conv → recovery.proj + Reconvery.proj(双填)
    for d in ["patchrecovery2d","patchrecovery3d"]:
        v = out.pop(f"{d}.conv.weight")
        for tgt in [f"{d}.recovery.proj.weight", f"{d}.Reconvery.proj.weight"]:
            if tgt in msd: out[tgt] = v.reshape(msd[tgt].shape)
    # Sampler → sampler;丢 conserv.*
    ...
    return out
sdk2 = remap_state(ck["model_state_dict"], st.state_dict())
r = st.load_state_dict(sdk2, strict=False)
if len(r.missing_keys) > 0:
    print(f"[警告] load 后仍缺 {len(r.missing_keys)} key(随机init): {r.missing_keys[:5]}")   // ★必看这行!
决赛保命:永远盯 missing_keys

加载权重后一定看 missing_keys 是不是 0(或只剩无害 buffer)。非 0 = 有层在用随机初始化 = 分数会无声暴跌。这是"明明权重对、分数却很烂"的头号原因。L1 推理里 load_state_dict(strict=False) 也一样,务必核对。

6fp32 口径:为什么判优要用 fp32↑

这段干啥:整个 evalm 在 fp32 下跑。bo3b 这类高激活权重在 fp16 前向会 NaN(L3/L1 讲过的残差溢出),fp32 才 finite,所以判优口径用 fp32 最稳最准。模型构造时不 .half(),输入也 torch.float32。

score15_fp32.py · L13 / L53(fp32 关键)
import maxvit3d_student as M; M.set_sdpa(False)        # 同 L1,关 DCU 上费显存的 SDPA
st = MaxVit3DStudent(...).to(dev).eval()              # ★不 .half() → 全程 fp32(bo3b 不 NaN)
三种数值口径对应关系(把三课串起来)

判优用 fp32(score15_fp32,最准);训练用 bf16(L3,稳且快);部署用 fp16 + ENC_FP32(L1,只把溢出的残差流升 fp32)。三处口径不同但要相互印证:fp32 选出的好权重,部署 fp16 后用 score15_dcu 复测,确认没掉分才提交。

基线数字的口径说明(别被数字绊住)

代码里写死的 fp32 口径 bo3b 基线 ≈ 38.44(和最终评测 W=38.4387 吻合)。用户记录里还有个 bo3b 判优参照 37.6276,那应是另一口径(如 score15_dcu 的 fp16 fast_forward,或不同 pairs 数)下的数。判优铁律不是记死某个数,而是:新候选和 bo3b 在【完全相同口径】下比 W,超了才留。换数据/换脚本就重测基线,别跨口径比。

8三个评测脚本的分工(配合用)↑

脚本调用角色
score15_fp32.pypython score15_fp32.py student.pth选权重(最准 fp32 判优)
score15_dcu.pypython score15_dcu.py student.pth libgemm.so部署复测(matrix-core fp16,最接近评测;验证 L1/L2 没掉分)
score15_diff.pypython score15_diff.py w1.pth bo3b.pth逐通道诊断(哪些通道涨/跌 → 指导 L3 下一搏补哪里)

score15_dcu.py 内部会 cp libgemm.so、设 FAST_STREAM=1 ENC_FP32=1,用 L1 的 CppRunner fast_forward 跑——它把 L1/L2/L3 全链路串起来打一个真实分,是提交前最后一道关。

动手实践 1 · 打一次分跑 python score15_fp32.py data/checkpoints/student.pth,记下 W15/W69/RMSE15/ACC15,确认终端没有 [警告] load 后仍缺 N key(有就是 remap 没填全)。

收小结 + 四课闭环↑

L4 你掌握了什么
  • W 公式:RMSE 项 + ACC 项,各 min(比值,1) 封顶,×20 = 满分 40;已封顶的通道别再优化,提分要找没封顶的。
  • evalm:对真值 ERA5 逐通道算 RMSE + ACC(异常相关);口径和 L3 选优一致。
  • W15/W69:官方按 W15;近地面 4 变量拖低 W15。
  • ★remap + missing_keys:训练命名 ≠ 部署命名,必须 remap;加载后盯 missing_keys=0,否则静默掉分。
  • fp32 判优:bo3b fp16 NaN,fp32 最稳;判优 fp32、部署 fp16、提交前 dcu 复测。
  • 判优:同口径超 bo3b 才留;换口径/数据重测基线。

四课闭环:L3 训练把模型练准 → L4 评测判优选出最好权重 → L1 推理把它又快又省地跑出来 → L2 matrix-core再省 121MiB。判优口径(L4)既指导训练选优(L3),又验证部署没掉分(L1/L2)。这就是 96.12 这套代码的完整工作流——每一分都能定位到一段代码、一个口径、一次实测。决赛换方向时,照这四课的代码与方法论,从 baseline 起逐项打分、逐项优化即可。
