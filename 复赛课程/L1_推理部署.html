读导读:这一课跑什么↑

评测脚本就一句 python inference.py。它会:读配置和数据 → 重建学生模型、加载 bo3b 权重 → 把模型交给 CppRunner(在 maxvit3d_cpp.py)→ CppRunner 把每一层的矩阵乘、注意力、归一化都换成我们手写的 HIP kernel 去算 → 在官方不可改的计时区里测单步时长 → 输出预报 .npy 和 time_record.json。

一句话抓住这两份文件的分工

inference.py = 总指挥:定档(开哪些优化)、加载、计时、优雅降级、存盘。maxvit3d_cpp.py(CppRunner)= 干活的:把 PyTorch 的前向一比一复刻一遍,但所有计算走 HIP/hipBLAS kernel,目标是和原 torch 前向 bit-exact(数值几乎一字不差),却更快、更省显存。

1inference.py 逐段讲解↑

文件位置:最优项目代码/01_推理部署/inference.py(233 行)。我们按执行顺序拆 5 块。

1.1 顶部环境变量:一行一个"优化开关"

这段干啥:在 import torch 之前设好几个环境变量,等于给这次推理"定档"。为什么必须在 import 前?因为 PYTORCH_CUDA_ALLOC_CONF 只在首次 CUDA 分配前设置才生效。

inference.py · L1–L9
import os
# 显存优化(U):分配器可伸缩、回收碎片(实测整卡峰值显著降)。必须在 import torch 前设
os.environ.setdefault("PYTORCH_CUDA_ALLOC_CONF", "expandable_segments:True")
# stem/recovery 流式分块数。大→GPU峰值低但 launch 多(V慢);小→V快但峰值高
os.environ.setdefault("N_TILES", "8")
os.environ.setdefault("FAST_STREAM", "1")   # 默认双叠加包:input流式 + recovery offload
os.environ.setdefault("ENC_FP32", "1")      # enc 轻量混合精度(解锁高激活权重 bo1/bo3b,避 fp16 NaN)
import torch
四个开关分别管什么(记住这张表,改档就靠它)
  • expandable_segments:True —— 让显存分配器能回收碎片,降整卡峰值(U)。无脑开。
  • FAST_STREAM=1 —— 566 档:输入连续 chunk 流式进 GPU + recovery 流式 offload,GPU 峰值 ~566MiB。需要 CppRunner 可用。
  • ENC_FP32=1 —— enc 段用"轻量残差-fp32"混合精度,解锁高激活权重(否则 bo3b 在纯 fp16 会 NaN)。几乎免费。
  • N_TILES —— stem/recovery 切几块。V 与 U 的权衡旋钮:块多省显存但慢、块少快但费显存。FAST_STREAM 时被自动设为 1。

怎么调用 / 怎么改:这些都用 setdefault,意味着你可以在命令行覆盖它们:FAST_STREAM=0 N_TILES=16 python inference.py。换方向时,这是你第一个该扫的旋钮组。

这段干啥:权重文件 student.pth 里不仅有参数,还存了一份结构配置 cfg(patch/embed/depths/heads…)。所以推理端不需要外部结构文件,直接照 cfg 把模型搭出来再灌权重。strict=False 容忍少量键不匹配(如 buffer)。

1.3 构 CppRunner + ★优雅降级(决赛保命设计)

这段干啥:尝试构建并初始化 CppRunner;一旦 .so 加载不了或初始化报错,except 兜底回退到普通 torch 前向,绝不让评测崩。这是"宁可慢、不可挂"的工程纪律。

inference.py · L98–L126
infer = None
try:
    from maxvit3d_cpp import CppRunner
    runner = CppRunner(model)
    runner.init()        # rocblas/gemm_init + warmup(★计时区外,一次性消懒加载)
    if FAST_STREAM:
        _buf_s, _buf_u = _MCP.fast_make_buffers(_NREC)   # 计时外预分配,复用
        with torch.no_grad():       # 自检必须走 fast_forward(否则峰值被抬高)
            _pk = _MCP.prepack_input(torch.randn(1,72,721,1440, dtype=torch.float16, device='cpu'))
            runner.fast_forward(_pk, _buf_s, _buf_u); del _pk
    else:
        with torch.no_grad():       # 628 档自检:跑一次不报错才采用
            _t = torch.randn(1,72,721,1440, dtype=torch.float16, device='cuda:0')
            runner(_t); del _t
    infer = lambda x: runner(x)
    print("✅ CppRunner (HIP/hipBLAS) enabled")
except Exception as _e:
    print(f"⚠️ CppRunner unavailable ({_e}); fallback to torch forward")
    FAST_STREAM = False
    def infer(x):
        with torch.autocast('cuda', dtype=torch.float16):
            return model(x)
为什么自检要在计时区外先跑一次

第一次跑任何 kernel 都有"懒加载"开销(rocBLAS 选算法、HIP 模块装载),首样本能比稳态慢几秒。init() + 自检把这些全挪到计时区外,让评测计到的每个样本都是"热"的稳态时延。这是 V 分能打高的隐形前提——计时区里只剩纯计算。

怎么改适配:这个 try/except 结构是模板,换方向时直接复用:任何"高风险加速"(自定义 .so、特殊 kernel)都该包在 try 里,except 回退到能跑的稳妥路径。决赛环境陌生,这能救命。

1.4 warmup + 后台预取(都在计时区外)

这段干啥:两个"零风险纯利好"优化。① warmup:计时前再空跑一次前向,暖好剩余的 torch reshape/pad kernel;FAST_STREAM 时 warmup 必须走 fast_forward(否则峰值统计被抬高)。② 后台线程预取下一个样本的数据(取数/numpy 在 C 层释放 GIL,可与 GPU 计算并行),省掉每样本的取数等待。

inference.py · L140–L158(节选)
torch.cuda.empty_cache()   # 释放 warmup 碎片,样本循环从干净 reserved 增长(降整卡瞬时峰值)
import threading, queue
def _prefetch(it, q, n=2):
    for d in it: q.put(d)
    q.put(None)
_q = queue.Queue(maxsize=2)
threading.Thread(target=_prefetch, args=(iter(test_dataloader), _q), daemon=True).start()

1.5 样本循环 + ★AI4S 计时区(一行都不能改)

这段干啥:对每个样本:把输入拼成 [1,72,721,1440](地面 4 通道 + 3 静态掩膜 + 高空 65 通道)→ 在官方标注的计时区里调前向 → 反归一化存盘。计时区由 start_time / model前向 / torch.cuda.synchronize() / end_time 四行组成,标注 "AI4S 不可更改" —— 位置和写法绝不能动。FAST_STREAM 把"数据搬运/重组"挪到计时区外,计时区里只剩 fast_forward 纯计算。

inference.py · L182–L196(FAST_STREAM 分支)

计时区铁律(决赛同样适用)

① synchronize() 必须有 —— DCU 算子异步,不同步会把 GPU 真实耗时算少(看着快其实作弊,会被判违规)。② 计时区内只放 model 前向 —— 任何数据搬运、reshape、存盘都要挪出去。③ 这四行的位置/写法是官方给的,不要改、不要挪、不要加东西进去。这是 V 分合规的红线。

2maxvit3d_cpp.py 逐段讲解(CppRunner)↑

文件位置:最优项目代码/01_推理部署/maxvit3d_cpp.py(496 行)。核心思想一句话:照着 maxvit3d_student.py 的前向流程,把每个算子换成 ctypes 调 HIP kernel,reshape 仍用 torch view,做到 bit-exact。

2.1 ctypes 加载两个 .so + 声明函数签名

这段干啥:用 ctypes.CDLL 把两个手写库加载进来,并用 argtypes 声明每个 C 函数的参数类型(指针 + 整数 + stream)。libgemm.so 给 GEMM/LayerNorm/SwiGLU,libflashattn.so 给 flash 注意力 + RMSNorm。

maxvit3d_cpp.py · L19–L43(节选)
_LIBG = ctypes.CDLL("libgemm.so")        # matrix-core GEMM 库(L2 的主角)
_LIBF = ctypes.CDLL("libflashattn.so")   # flash 注意力 + RMSNorm
# 声明 C 函数签名:全是 void* 指针 + int 维度 + void* stream
_LIBG.gemm_linear_fp16.argtypes = [ctypes.c_void_p]*4 + [ctypes.c_int]*3 + [ctypes.c_void_p]
_LIBF.flash_qkv_launch_h.argtypes = [ctypes.c_void_p]*4 + [ctypes.c_int]*2 + [ctypes.c_void_p]

怎么调用底层:关键技巧是把 PyTorch 张量当成裸指针传给 C —— tensor.data_ptr() 拿到显存地址,torch.cuda.current_stream().cuda_stream 拿到当前 stream,这样 HIP kernel 和 torch 在同一条流上、共用同一块显存,零拷贝。

2.2 五个算子封装:Python 包一层、底层走 HIP

这段干啥:把"形状整理 + 调 C 函数 + 形状还原"包成好用的 Python 函数。以 linear(全连接/GEMM)为例,它把任意维输入压成二维 [M,K]、调 gemm_linear_fp16、再 reshape 回去。

maxvit3d_cpp.py · L50–L62
def linear(x, W, b=None):
    """x:[...,K] → [...,N]; W:[N,K]; b:[N] or None. fp16."""
    *lead, K = x.shape;  M = prod(lead);  N = W.shape[0]
    x2 = x.reshape(M, K).contiguous()
    out = torch.empty(M, N, dtype=torch.float16, device=x.device)
    _LIBG.gemm_linear_fp16(c_void_p(x2.data_ptr()), c_void_p(W.data_ptr()),
                           c_void_p(bp), c_void_p(out.data_ptr()), M, N, K, _stream())
    return out.reshape(*lead, N)

同理还有 rmsnorm(归一化)、layernorm、swiglu_w(门控 FFN:两次 linear 中间夹 silu·gate)、attention_window(flash 窗口注意力)。这五个就是整个网络的全部"计算原语"——网络再大,也是它们 + reshape 拼出来的。

为什么这样设计能 bit-exact

形状变换(reshape/permute/pad)全部仍用 PyTorch 的 view 操作(和原模型一字不差),只把"算"这一步换成 HIP。HIP kernel 内部用 fp16 输入 + fp32 累加,和 torch autocast 的数值行为对齐,所以整条前向下来 max diff < 1e-2(fp16 噪声级),W 分不变。

2.3 CppRunner 预算 + init(把能提前算的都提前)

这段干啥:__init__ 里把"权重固定、每次都一样"的东西预算好缓存起来:注意力的 scale(logit_scale 取指数)、相对位置偏置表(RelPosBias3D 查好的 [H,N,N])。这些不必每次前向重算。init() 在计时区外做 gemm_init + 微 warmup,消掉所有 kernel 首次懒加载。

maxvit3d_cpp.py · L178–L195(节选)
# 预算 scale[h]=clamp(logit_scale,max=log100).exp(),每块一次(权重固定)
for name, p in model.named_parameters():
    if name.endswith("attn.logit_scale"):
        self._scales[...] = torch.clamp(p, max=math.log(100.)).exp().reshape(-1).float()
# 预算相对位置偏置表 [H,N,N],每块一次
for n, mod in model.named_modules():
    if n.endswith(".attn.bias"): self._bias[...] = mod().detach()[0].half()

def init(self):
    _LIBG.gemm_init()        # ★L2 重点:matrix-core 版这里【不】调 rocblas_initialize → 省 121MiB
    self.micro_warmup()      # 用小张量预触发每个 torch elementwise/pad kernel 的首次加载
    torch.cuda.synchronize()

2.4 前向编排:逐层复刻 AttnFFN

这段干啥:_ffn_block 复刻学生模型一层的结构:pre-RMSNorm → 注意力 → LayerScale 残差;pre-RMSNorm → SwiGLU → LayerScale 残差。_attn_block 复刻"窗口划分 → qkv linear → flash → 窗口还原 → proj"。这就是把 PyTorch 的 forward 用我们的算子重写一遍。

maxvit3d_cpp.py · L245–L256
def _ffn_block(self, prefix, blk, x, res, H):
    ls1, ls2 = self.sd[prefix+".ls1"], self.sd[prefix+".ls2"]
    h = rmsnorm(x, self.sd[prefix+".norm1.weight"])              # 我的 HIP rmsnorm
    h = self._attn_block(prefix+".attn", h, res, blk.mode, H)     # flash 注意力
    x = x + ls1 * h                                              # LayerScale 残差
    h2 = rmsnorm(x, self.sd[prefix+".norm2.weight"])
    h2 = swiglu_w(h2, self.sd[prefix+".mlp.w12.weight"], ...)        # 我的 HIP swiglu
    return x + ls2 * h2

怎么改适配:如果决赛换的模型层结构不同(比如多一个 norm、换激活),你只需照着新模型的 forward 改这里的编排顺序,算子库不用动(linear/norm/silu 还是那几样)。这就是"编排"和"算子"解耦的好处。

2.5 流式 stem / recovery(U 的大头来自这里)

这段干啥:stem(把气象网格切成 token)和 recovery(把 token 还原成网格)是最吃显存的两步(高分辨率)。_embed 不一次性处理整张图,而是沿纬度切成 N_TILES 条 strip,每条:从 CPU 切片搬 GPU → 局部 pad → linear → 写进预分配 buffer。这样输入永不整体进 GPU(峰值 -142MiB),且不 torch.cat(省 token 输出翻倍)。全程数学等价。

maxvit3d_cpp.py · L283–L298(节选)
n_tiles = int(os.environ.get("N_TILES", "8"))   # ★旋钮:strip 数
out = torch.empty(1, O, nz, nH, nw, dtype=torch.float16, device="cuda:0")  # 预分配输出
for s in range(0, nH, rows):           # 逐 strip
    strip = x5[:, :, :, a0:a1, :].to("cuda:0")    # ★从 CPU 切片才搬 GPU(input 流式)
    strip = F.pad(strip, (pl,pr,ptop,pbot,pf,pb))   # 局部 pad(不物化整张 padded)
    o = linear(blk, Wf, proj_b)                      # 这条 strip 的 embed
    out[:, :, :, s:e, :].copy_(o); del strip, blk, o  # 写 buffer,不 cat

_recovery 同理,还多一个 REC_OFFLOAD 开关:开了就把输出 buffer 放 CPU,每条 strip 算完即 D2H,GPU 端不存 output(更省 U,但每 strip 多 ~52ms D2H,V 变慢)。评测只算 GPU 显存,CPU 不计,所以这是纯 U 利好、代价在 V。

2.6 ENC_FP32:轻量残差-fp32 混合精度(解锁高 W 权重)

这段干啥:bo3b 这类高精度权重在纯 fp16 下,enc 段的残差累加值会 > 65504(fp16 上限)→ NaN。解法很巧:子层(注意力/SwiGLU)还是走 fp16 的 HIP kernel(快、省显存、不引入 torch matmul 库),只把"残差流 x"保 fp32。因为溢出根因是残差累加,子层输出本身 fp16 装得下。这样既不 NaN,又几乎不增显存、不丢速度。

maxvit3d_cpp.py · L411–L426(节选)
def rmsnorm_fp32(x32, w):                  # fp32 上归一(x32 可能 >65504,必须 fp32)
    n = x32 * torch.rsqrt(x32.pow(2).mean(-1,keepdim=True)+1e-6)
    return (n * w.float()).half()            # 归一输出 ~O(1) 安全,cast fp16 给子层 kernel
xf = xx.float()                            # ★残差流保 fp32
for i, blk in enumerate(self.m.enc):
    h = rmsnorm_fp32(xf, ...);  h = self._attn_block(...)   # fp32 prenorm → fp16 attn
    xf = xf + ls1 * h.float()              # ★fp32 残差累加(不溢出)
    h2 = swiglu_w(rmsnorm_fp32(xf, ...), ...)
    xf = xf + ls2 * h2.float()
return xf.half()                           # enc 输出 cast 回 fp16 进 downsample
迁移价值

"找到溢出的唯一根因(残差累加),只对那一处升精度,其余保持低精度"——这是混合精度的精髓。换方向遇到 fp16 NaN,先用 PROFILE_MEM / 打印定位是哪一步溢出,再做最小升精度,而不是无脑全 fp32(那会丢光速度和显存优势)。

2.7 fast_forward:566 档的三件套

这段干啥:566 档的整条前向。和普通 __call__(628 档)比,区别全在 stem/recovery:① 输入预排成连续 strip-major pinned(在计时区外 prepack_input 做),embed 逐连续 chunk H2D(连续切片走满 DMA,3ms;而非 strided gather 44ms);② recovery 写连续 pinned buffer 异步 D2H(output 不在 GPU resident,省 128MiB);③ 末尾一次 synchronize。中间骨干(enc/mid/dec)完全一样。

maxvit3d_cpp.py · L380–L397(fast_forward 主体)
def fast_forward(self, packed, buf_s, buf_u):
    s, u = self.fast_embed(packed, NC_IN)            # ① 连续 chunk 流式 embed
    xx = torch.concat([s.unsqueeze(2), u], dim=2)
    xx = self._run_enc(xx, rf); skip = xx            # enc(ENC_FP32 在此生效)
    xx = self._downsample(xx, rf)
    xx = self._run_stage("mid", self.m.mid, xx, ...)   # 1/4 分辨率主干
    xx = self._upsample(...); xx = self._run_stage("dec", ...)
    output = torch.concat([xx, skip], dim=-1)         # U 形 skip
    ms = self.fast_recovery("patchrecovery2d", rin2, (1,721,1440), buf_s, NREC)  # ② 异步 D2H
    mu = self.fast_recovery("patchrecovery3d", rin3, (13,721,1440), buf_u, NREC)
    torch.cuda.synchronize()                          # ③ 末尾一次同步
    return ms, mu
628 档(__call__)vs 566 档(fast_forward)怎么选

628 档(FAST_STREAM=0):输入整体进 GPU,embed 快、V 最稳;峰值含输入。566 档(FAST_STREAM=1):流式,峰值低 ~60MiB、U 更高;V 略敏感。最优分用 566,因为它在 V 不超阈值的前提下把 U 压到最低。决赛先用 628 拿稳保底分,再试 566 冲 U。

3怎么改适配新方向(决赛实战)↑

换了什么改哪里
换权重(同结构)只换 student.pth 路径;cfg 内嵌会自动重建结构。
换模型层结构改 CppRunner 的 _ffn_block/_attn_block 编排顺序,算子库(linear/norm/silu)不动。
显存超了调大 N_TILES、开 FAST_STREAM=1 / REC_OFFLOAD=1;牺牲 V 换 U。
时延超了FAST_STREAM=0 用 628 档、调小 N_TILES;牺牲 U 换 V。
fp16 NaN定位溢出层 → 对那一处用 ENC_FP32 式"残差流升 fp32"。
.so 在新环境加载不了不用慌——优雅降级会自动回退 torch 前向,先拿到能跑的分,再排查/重编 .so。
