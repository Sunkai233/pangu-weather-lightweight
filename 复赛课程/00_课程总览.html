读开篇:这套课要把你练成什么样

复赛(决赛)的设定是:换一个方向、稍微提高要求、只给你一天时间适配,而且不能依赖大模型,要你自己独立完成。这意味着你不能只"会按步骤跑通本次的脚本",而要真正理解每一步为什么这么做、卡住了去哪查、换了题目怎么迁移。这套课的终点不是"看懂",而是"换个题你也能在一天里自己把分打上去"。

学完这 20 课,你应当能独立做到
  • 看懂一个深度学习模型的推理过程,说清它慢在哪、占显存在哪(memory-bound 还是 compute-bound)。
  • 从零写一个 HIP kernel,用 hipcc 编译、在海光 DCU 上跑起来,并会调 hipBLAS 做矩阵乘。
  • 独立完成 SCNet 二跳登录 → 找计算节点 → 进容器 的全套操作,会用 squeue / hy-smi / nohup / tmux,踩坑能自救。
  • 把一个大模型做蒸馏 → 量化 → kernel/显存/时延优化 → 评测打分的完整流水线。
  • 面对陌生新题:先跑通官方 baseline、用评测定位瓶颈落在 U/V/W 哪一项,再针对性优化、快速迭代提交。
本项目的"三分制"是贯穿全课的指挥棒

先导杯赛题二总分 100,拆成三块,记住它们,后面每一课都围着它转:

  • W · 预测性能(精度,约 40 分)——预报场对真值 ERA5 的纬度加权 RMSE/ACC,不能比教师差太多(达标线 RMSE ≤ 1.3× 教师)。
  • U · 轻量化(参数+显存,约 40 分)——参数量较教师下降(达标线 ↓70%),以及实测推理峰值显存。
  • V · 推理时延(约 20 分)——海光 DCU 上单步推理时长越短越好。

本次成绩参照(让你知道"好"长什么样):教师 Pangu 64M / RMSE 1.00× / 单步 331ms;最优学生约 4.46–5.83M(教师 7–9%)/ 1.05–1.14× / DCU 手写 HIP 17–18ms。这就是要复现并迁移的能力。

一模块一 · 推理框架入门(大白话)↑ 回顶部

目标:把"模型推理 / 框架 / 算子 / 优化 / ONNX"这些词彻底讲明白,让你之后看任何优化都知道"它在优化哪一环、为什么有用"。这一模块不写底层代码,重在建立正确的脑内模型。

L1
深度学习推理到底是什么
01_推理是什么.html
45 min
学完能:用自己的话讲清"训练 vs 推理"的区别,说出一次推理在干什么(一堆矩阵乘 + 激活),以及"前向传播"为什么是一串算子。
知识点
  • 训练(学权重,要反向传播+优化器)vs 推理(权重固定,只走前向)——本项目你部署的就是推理。
  • 一次前向 = 一连串"层"(卷积/注意力/归一化/全连接),每层本质是矩阵运算 + 非线性。
  • 张量(tensor)是什么:多维数组;形状(shape)/数据类型(dtype: fp32/fp16)。
  • 以盘古为例:输入气象网格 → 一串层 → 输出未来气象网格,中间没有"思考",只有算。
纯概念讲解含诊断/方法论
L2
推理框架与"算子"概念(PyTorch eager vs 部署优化)
02_框架与算子.html
50 min
学完能:解释什么是算子(operator)、什么是推理框架,以及"PyTorch 一边算一边调度(eager)"为什么没榨干硬件、部署框架做了哪些事。
知识点
  • 算子 operator:框架里的"一种运算单元"(MatMul/Conv/Softmax/LayerNorm…),模型 = 算子搭起来的计算图。
  • PyTorch eager 模式:写一行算一行,灵活但每个算子单独启动、中间结果反复进出显存——慢。
  • 部署/推理框架(TensorRT / 海光 MIGraphX)做什么:图优化、算子融合、选最快的 kernel、固定形状提速。
  • "同一个模型,换个跑法能快好几倍"——这就是 V 分(时延)的全部来源,埋下后面手写 kernel 替换慢算子的伏笔。

L3
为什么要优化:显存约束与时延约束
03_为何优化_显存与时延.html
50 min
学完能:区分"显存瓶颈"和"时延瓶颈",理解 memory-bound vs compute-bound 这条贯穿全课的判优铁律,知道优化前必须先定位瓶颈。
知识点
  • 显存放什么:权重 + 激活(中间结果)。反直觉关键:本项目激活占 99%、权重仅 1%(单样本峰值约 1GB 里激活 1056MB)。
  • 时延从哪来:算得慢(compute-bound)还是搬数据慢(memory-bound)。Roofline / 算术强度大白话版。
  • 盘古学生的特点:参数小(几 M)、激活巨(全分辨率 13 万 token)→ 大部分模块是访存受限(与 LLM 相反),所以主战场是访存不是算力。
  • 判优铁律:先定位瓶颈方向再动手,方向错了白干;任何"X 比 Y 快"必须在目标硬件实测。

ONNX 与图优化:模型怎么从训练框架走向部署
04_ONNX与图优化.html
45 min
学完能:说清 ONNX 是什么(模型的通用中间表示),会描述"PyTorch → ONNX → 推理引擎"链路,知道导出常见坑。
知识点
  • ONNX = 跨框架的"模型交换格式",把网络存成一张标准计算图,供 TensorRT/MIGraphX/onnxruntime 加载。

L9
进阶 kernel:flash 注意力思想 + GEMM 分块 tiling
09_进阶_flash与分块.html
85 min
学完能:讲清 flash attention 的核心(不物化 N×N、在线 softmax、tiling 进 LDS),看懂本项目手写 flash 窗口注意力核,理解它为何在 DCU 上 5.3× 快过 PyTorch SDPA。
知识点
  • 标准注意力为什么慢/费显存:中间 N×N 分数矩阵反复进出 HBM。
  • flash 三招:tiling(Q/K/V 切块进 LDS)+ online softmax(只维护跑动 max/sum/输出)+ 绝不物化大矩阵。
  • GEMM 分块 tiling:把热数据搬进 LDS/寄存器反复用,减少 HBM 往返;合并访存 + 避免 bank conflict。
  • 本项目实战拆解:窗口自注意力 144 token、6 头、含 QK-Norm + 相对位置偏置;1 线程 = 1 query 行,分数只在寄存器里活一瞬;v1=2.19ms,wavefront 协作版反而慢 4.4×(再次印证 DCU 偏好独立线程)。
  • 算子融合思想:把 RMSNorm/partition 折进大核,消除小算子 launch 开销。

矩阵核指令 v_mmac + 反汇编看机器码(选学高阶)
10_矩阵核与反汇编.html
75 min
学完能:理解什么是矩阵核(对标 NVIDIA Tensor Core),知道 gfx936 用 v_mmac 而非 AMD 的 v_mfma,看懂"反汇编 + 逆向 fragment 布局 + 手写矩阵核 GEMM 替 rocBLAS"这条破解路线的逻辑。
知识点
  • 矩阵核是什么:一条指令做 16×16×16 矩阵乘加,比标量快一个量级;NVIDIA=Tensor Core(mma)、AMD=MFMA(v_mfma)。
  • 本项目独有发现:海光 gfx936 的矩阵核指令是 v_mmac(__builtin_amdgcn_mmac_f32_16x16x16f16),不是 AMD 的 v_mfma——照搬 AMD 代码会失败。

量化与显存优化(U 分的两把刀)
17_量化与显存优化.html
75 min
学完能:对模型做 INT8/FP16 权重量化并评估精度损失,理解"量化是存储刀不是显存刀",会判断显存峰值真正卡在哪、怎么降。
知识点
  • 量化原理:fp32→fp16→int8;per-channel vs per-tensor;权重量化 vs 激活量化(W8A8)。
  • 本项目结论(关键且反直觉):INT8 per-channel 近无损(+0.08%)优于 FP8;FP8 全面不如 INT8(蒸馏小模型权重分布集中);端到端 W8A8 要配 SmoothQuant(INT8 激活 +0.67%,FP8 不吃 smooth)。
  • 三把刀分清:量化主要帮"模型大小"(11.66→7.73MB)进 U 分;不帮显存(激活占 99%);加速对小矩阵有限。
  • 显存优化:激活在哪(高分辨率 patch embed/recovery 是大头);真降峰值靠空间分块 tiling + 激活量化;负结果:Flash/SDPA 对峰值省 0%(峰值是特征图不是注意力矩阵)。
  • 清醒判断:单样本峰值约 1GB,对 64GB 的 DCU 远非瓶颈,降显存优先级要看题目要求。
