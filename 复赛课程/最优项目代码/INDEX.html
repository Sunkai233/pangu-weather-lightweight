本文件夹把分散在提交包、cpp_stage1 开发目录、abc66 训练机三处的最优项目核心代码收齐到一处,按"推理 / matrix-core / 训练 / 评测 / 参考"五个模块归档。每个文件都标注:①原位置、②干啥、③怎么调用。这是后续逐代码 HTML 讲义的素材底座。

读这套代码是什么 · 最优配置↑

整套方案做的事:用一个 5.19M 的轻量学生 MaxViT-3D 通过知识蒸馏 + 真值双监督逼近官方 Pangu 教师(64.22M),再叠加全 HIP/hipBLAS 路由前向(CppRunner)+ 手写矩阵核 GEMM 库(libgemm.so,纯 v_mmac)+ 流式显存优化,在海光 DCU 上同时把 U(模型大小+显存)、V(时延)、W(精度)三项分数打高。

★ 最优分配置(本次最高分这条路径用的开关与组件)
  • 权重:bo3b 学生权重(双叠加包,真值监督蒸馏产出;放在 data/checkpoints/student.pth,需用下载链接取,见下文)。
  • 推理开关:FAST_STREAM=1(输入连续 chunk H2D + recovery 流式 offload,降 GPU 峰值)+ ENC_FP32=1(enc 轻量残差-fp32 混合精度,解锁高激活权重避 fp16 NaN)。两者都是 inference.py 顶部默认开。
  • matrix-core 库:libgemm.so 来自 gemm_lib_mmac.hip —— 用 gfx936 矩阵核指令 v_mmac 手写 GEMM,gemm_init 不调 rocblas_initialize → 不加载 Tensile 库 → 省约 155MiB 显存(直接抬 U 的显存分)。
  • 注意力:libflashattn.so 在线 flash 窗口注意力(不物化 N×N 分数矩阵),替 DCU 上没优化好的 torch SDPA。
三分制 ↔ 代码模块对应(全局指挥棒)
  • W(精度,~40 分) ← 模块 03 训练(distill_truth.py / distill_scnet.py)。
  • U(参数+显存,~40 分) ← 学生小(5.19M)+ fp16/INT8 权重存储 + matrix-core 省 Tensile 155MiB + 流式分块降激活峰值。
  • V(时延,~20 分) ← 模块 01 的 CppRunner 全 HIP 前向(matrix-core GEMM + flash 注意力 + 快 recovery)。

口径说明:提交包内 优化说明文档.md 记录的是较早的"纯 PyTorch fp16"基线(官方 15 指标口径 W=35.63 / 总分 94.04);本目录收的是在其之上叠加 bo3b 权重 + matrix-core 库 + FAST_STREAM 的更高分路径。数字以你在 DCU 上 score15_dcu.py 实测为准。

推理入口

02matrix-core HIP 模块(U 显存 · 手写 v_mmac)↑

本项目最硬核的一块:发现海光 gfx936 的矩阵核指令是 v_mmac(不是 AMD 的 v_mfma),通过反汇编 + 独热探针逆向出 fragment 寄存器布局,手写出 bit-exact 的矩阵核 GEMM 库替掉 rocBLAS——关键收益是 gemm_init 不加载 Tensile 库省约 155MiB 显存。下面按"生产库 → 迭代历程 → 逆向探针 → 反汇编工具 → 对照基线"排列。

gemm_lib_mmac.hip
生产版 matrix-core 库
原位置cpp_stage1/gemm_lib_mmac.hip
干啥编出最优分用的 libgemm.so。核心是 mmac_gemm 模板核:LDS-tiled、用 __builtin_amdgcn_mmac_f32_16x16x16f16 做 16×16×16 矩阵乘(fp16 输入 / fp32 累加),按实测逆向的 fragment 布局(lane L: r=L%16, g=L/16; a_frag[i]=A[r][g*4+i]; C acc[i]=C[r][g+i*4])。gemm_linear_fp16 按 (M,N,K) 形状选最优 tile(极小 M 用 32×32、大 N 用 128×256、通用 64×64)。gemm_init 故意不调 rocblas_initialize → 不加载 Tensile → 省 155MiB,只用极小张量 warmup 触发模板核懒加载。另含沿用的 layernorm/swiglu 核。
怎么调用
bash · 编译并替换
hipcc -O3 -shared -fPIC --offload-arch=gfx936 gemm_lib_mmac.hip -o libgemm.so
cp libgemm.so /path/to/submit_pw/libgemm.so   # CppRunner 自动从同目录加载
gemm_mmac.hip · gemm_mmac2/3/4.hip
优化迭代历程
原位置cpp_stage1/gemm_mmac{,.2,.3,.4}.hip
干啥矩阵核 GEMM 从能跑到追平 rocBLAS 的演进,讲义里逐版讲优化思路:gemm_mmac.hip=v1 正确性优先(1 wave/block,直接 global 读 fragment);gemm_mmac2.hip=LDS-tiled 复用;gemm_mmac3.hip=LDS 双缓冲 + 大 tile;gemm_mmac4.hip=寄存器级 fragment 预取 + 深 K-unroll。最终产线版即 gemm_lib_mmac.hip。
怎么用学习/对比用,可单独编译跑 self-test:hipcc -O3 --offload-arch=gfx936 gemm_mmac2.hip -o t && ./t。
gemm_wint8.hip
仅权重 INT8 矩阵核
原位置cpp_stage1/gemm_wint8.hip
干啥权重 INT8 量化版 GEMM:W 存 int8[N,K] + per-N-channel scale,kernel 载入 LDS 时反量化 int8→fp16(×scale)再走 v_mmac;A 保 fp16、matmul 全 fp16 → 近无损(对应"权重 INT8 per-channel +0.08%")。再省权重显存约 97MiB,是 U 的进一步杠杆。
怎么用同样 hipcc -shared -fPIC --offload-arch=gfx936 编成库,需配套把权重量化成 int8 + scale 后传指针。属进阶可选项。
mmac_probe / layout / frag / solve / verify / brute / btile.hip
fragment 布局逆向探针组
原位置cpp_stage1/mmac_*.hip(7 个)
干啥破解 v_mmac 操作数/累加器寄存器布局的全过程(讲义讲"怎么逆向硬件指令"):
  • mmac_probe.hip:验证指令存在 + 测峰值算力(纯寄存器反复 v_mmac,无访存)。
  • mmac_verify.hip:A=B=全1 → C 每元素=16,确认是 16-deep 点积;再用结构化输入推映射。
  • mmac_layout.hip:喂"单热点"(只设某一 lane/槽=特殊值),看 C 哪些位置变 → 反推映射。
  • mmac_frag.hip / mmac_solve.hip:用受控/独热 A、B 对比 CPU 真值,自动推断 a_frag/b_frag/c_frag 的 lane→(行,列) 映射。
  • mmac_brute.hip:暴力搜布局组合找 bit-exact 那一组。
  • mmac_btile.hip:专解 B fragment(B=单位阵,C 应=A)。
怎么用逐个 hipcc -O3 --offload-arch=gfx936 mmac_solve.hip -o t && ./t,看打印的布局结论。这些是"做出 gemm_lib_mmac.hip 之前"的探路代码。
gcn_decode.py · gcn_scan.py · isa_probe.sh
反汇编 / 指令探测
原位置cpp_stage1/gcn_decode.py · gcn_scan.py · isa_probe.sh
干啥isa_probe.sh:用 hipcc 内联汇编逐条试 gfx936 支不支持某矩阵/点积指令(v_pk_fma_f16 / v_dot* / v_mfma* …),回答"rocBLAS 的算力来自哪种指令"。gcn_decode.py:对 kernel 的 .text 二进制做 GCN5 指令分类解码,统计 VOP3P(packed fp16 FMA / dot / mfma)、VALU、LDS、访存占比。gcn_scan.py:位置无关扫描,统计关键 FMA 指令出现频次。
怎么用
bash · DCU 宿主机
bash isa_probe.sh                       # 看哪些指令编译通过
# 先反汇编出 .text 再解码:
hipcc --offload-arch=gfx936 -c gemm_mmac.hip -o k.o
roc-obj-extract / llvm-objdump -d k.o > k.txt  # (取 .text 段)
python gcn_decode.py k.bin                # 指令分类统计
python gcn_scan.py  k.bin                 # FMA 指令频次
gemm_lib.hip · gemm_bench.hip
rocBLAS 对照基线
原位置cpp_stage1/gemm_lib.hip · gemm_bench.hip
干啥gemm_lib.hip:用 hipBLAS/rocBLAS 实现同接口 GEMM(gemm_init 调 rocblas_initialize 把 Tensile 懒加载移到计时区外消首样本 3.5s)——这是手写 matrix-core 版的对照,也是"如果不想手写就用库"的稳妥退路。gemm_bench.hip:手写核 vs rocBLAS 逐 variant 计时 + 结果对拍(max abs diff),证明手写 bit-exact 且不慢。
怎么用hipcc -O3 --offload-arch=gfx936 gemm_bench.hip -lrocblas -o bench && ./bench。

distill_truth.py

原位置cpp_stage1/score15_{fp32,dcu,diff}.py
干啥都按官方 15 个气象指标 + W 公式(vs 教师 Pangu)算分,口径不同:
  • score15_fp32.py:纯 fp32 forward(bo3b 在 fp16 会 NaN,fp32 finite),W 判优最准。在 era5_real/2000 跑。
