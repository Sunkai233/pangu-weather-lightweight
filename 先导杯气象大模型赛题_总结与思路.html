二、赛题任务到底要做什么

在国产科学智算平台 OneScience(配套 OneSkills 知识/能力库)与国产加速卡上, 对官方 pangu-weather(盘古气象)大模型做轻量化 + 推理性能优化, 用隐藏测试集做黑盒评测:在预测精度基本不掉的前提下,把模型变小、显存占用变低、推理变快。

背景动机是把气象大模型部署到低轨卫星(星上推理)——载荷、功耗、算力都受限,所以"又小又快又准"才是核心目标。

目标模型

pangu-weather 全量权重(3D Earth-Specific Transformer,0.25° 全球网格)。组委会提供其训练/推理源码与全量权重。

数据

ERA5 训练集 + 验证集 + 示例数据集;隐藏测试集仅用于评测,选手不可访问。

硬件

指定版 X86 处理器 + 国产加速卡 1 张(承办为曙光,工具链为 HIP/DTK,推测为海光 DCU,以官方为准)。

软件环境(已锁版本,务必对齐)

OneScience 0.3.0 python 3.11 torch 2.5.1 onnx 1.21.0 onnxsim 0.6.3 onnxconverter-common 1.16.0 tensorly 0.9.0 torch-pruning 1.6.1

强信号:组委会预装的库几乎"指明了路线"——onnx / onnxsim / onnxconverter-common(图简化 + FP16 转换)、 torch-pruning(结构化剪枝)、tensorly(张量分解)。这三条线就是出题人期望你用的轻量化武器。

三、评分标准拆解(初赛 100 分)

初赛总分 = U(轻量化 40) + V(推理时长 20) + W(预测性能 40),全部基于隐藏测试集黑盒评测。

U · 40
模型轻量化:体积 20 + 显存 20
U = (1 − 轻量模型大小原模型大小)i × 20  +  (1 − 轻量模型显存占用原模型显存占用)j × 20
"模型大小"= 解压后目录总大小 + 权重文件大小之和(含权重、配置、推理静态数据、查表文件等全部必需文件)。压缩越狠得分越高。
V · 20
推理时长:越快越高
S = 原模型平均样本推理时长轻量模型平均样本推理时长  ;  V = (1 − 1S)k × 20
"样本推理时长"= 样本加载到加速卡后 → 得到预测结果这一段。加速比 S 越大,V 越接近 20。计时相关代码禁止修改。
W · 40
预测性能:RMSE 与 ACC 双指标
W = 1N Σt [ max{(原 RMSEt轻量 RMSEt)l, 1} + max{(轻量 ACCt原 ACCt)m, 1} ] × 20
对每个气象指标 t 计算,再平均。精度持平基线 ≈ 40 分,超过基线还能更高。RMSE=均方根误差(越小越好),ACC=距平相关系数(越大越好)。

W 评测覆盖的气象指标

mean_sea_level_pressure10m_u_wind10m_v_wind2m_temperature geopotential 850/700/500specific_humidity 850/700/500 temperature 850/700/500u_wind_500v_wind_500

策略含义:i, j, k, l, m 为权重参数(官方设定,影响曲线陡峭度)。U+V 是"压缩/加速"得分, 能明确靠技术换分;W 的核心是守住精度别掉(理想是持平甚至略超基线)。 因此最优解是在"压得最狠 / 跑得最快 / 精度不塌"之间找 Pareto 最优点,而不是单维度极端。

四、规则红线(踩中直接出局/扣分)

❌ 绝对禁止

  • 修改基准测试中计时相关代码、改动标注"不可修改"的参数
  • 篡改/替换测试集,访问、推断、缓存隐藏测试集
  • 使用外部气象数据、其他气象模型权重、外部预训练权重或可直接产出气象预测的外部模型
  • 调用未授权在线服务、闭源二进制、外部大模型接口、不可审计的自动化工具来完成压缩/替换/出结果

✅ 明确允许

  • 对官方模型做剪枝、量化、蒸馏、结构压缩、推理优化
  • 设计 student 模型,但必须基于组委会数据 + 基准模型训练/蒸馏得到
  • 使用环境内提供的开源库与通用优化工具,结合气象学先验优化
  • 用大模型(Prompt/Skill)辅助开发,但需在代码注释、文档、答辩中说明,且能讲清原理
其他硬性要求:代码重复率 ≥ 50% 判抄袭;所有第三方代码/工具/配置必须在 README 头部 + 文档标注; 提交内容须在指定环境可复现、通过自动化黑盒测试。提交物 = 轻量模型训练+推理优化源码 + 轻量模型权重 + 优化说明文档。

五、技术路线与推进节奏

建议按"先量基线 → 摘低垂果实 → 结构压缩 → 蒸馏小模型 → 精度回补"分阶段推进,每阶段都用评测脚本量化收益。

阶段 0 · 基线与摸底 最优先
  • 跑通 OneScience + pangu-weather 全量推理,精确测准原模型大小、显存峰值、单样本推理时长、各指标 RMSE/ACC——这些是 U/V/W 所有分数的"分母",测不准后面全错。
  • 读穿评测脚本:计时段如何定义、哪些代码/参数不可改、显存如何统计、模型大小如何统计(目录+权重双口径)。
  • 看清 pangu-weather 结构:3D Earth-Specific Transformer、patch embedding、窗口注意力、多 lead-time 子模型,定位参数/计算/显存热点。
阶段 1 · 低成本高收益 先拿分
  • 半精度(FP16/BF16)推理:用 onnxconverter-common 做 FP16 转换 → 体积 ↓约 50%、显存 ↓约 50%、速度 ↑,精度几乎不变 → 直接把 U、V 拉起来。
  • ONNX 导出 + onnxsim 图简化 + 算子融合:去冗余节点、常量折叠,降低显存与延迟。
  • 国产加速卡图推理引擎编译优化(类 TensorRT 的 MIGraphX / DCU 推理栈):算子融合、kernel 自动调优、内存复用。
阶段 2 · 结构压缩 主战场
  • 结构化剪枝(torch-pruning / DepGraph):裁剪 MLP/注意力通道、减层、减窗口,显著降体积+显存+延迟;剪后需微调恢复精度。
  • 张量/低秩分解(tensorly:Tucker / CP / TT):分解大线性层与卷积核,压参数、减乘加。
  • 量化:先 PTQ(INT8/混合精度),精度掉太多再上 QAT(量化感知训练)。
  • 可组合:剪枝 + 分解 + 量化叠加,边压边用评测脚本看 U/V/W 的净变化。
阶段 3 · 蒸馏小模型 冲高分
  • 设计更小的 student(更窄/更浅的 3DEST、更大 patch 或更少 lead-time 子模型),用 ERA5 + teacher 输出做知识蒸馏。
  • 输出级 + 特征级蒸馏结合;按气象先验加权(重点指标/关键气压层/误差敏感区域权重更高),把精度集中保在评测的 15 个指标上。
  • 合规关键:student 必须从组委会数据/基准模型训练或蒸馏得到,不得换成任何外部预训练权重。
阶段 4 · 精度回补与 Pareto 调参 收尾
  • 微调/蒸馏回补精度,守住 W ≈ 40(理想略超基线);避免为压缩牺牲过多 RMSE/ACC。
  • 针对官方权重 i,j,k,l,m 的曲线特性,扫多组压缩率,画 压缩率 × 精度 Pareto 前沿,选总分最高的点。
  • 显存专项:batch=1、激活 FP16、in-place 算子、分块/patch 推理、清理推理期无用缓存——单独压 U 的显存那 20 分。
贯穿全程:① 固定随机种子 + 锁环境(Docker/版本)保证可复现;② README 头部标注所有第三方; ③ 大模型辅助处加注释;④ 每次改动都跑评测脚本记录 U/V/W,用数据驱动取舍,而不是凭感觉。

六、可参考的项目 / 论文 / 工具

气象大模型(理解结构与同类轻量化思路)

Pangu-Weather(华为,Bi et al., Nature 2023)
本赛题目标模型。官方发布 3D Earth-Specific Transformer 结构、推理代码与 ONNX 模型——优先吃透其结构与基线,定位可压缩点。
FourCastNet(NVIDIA,AFNO)/ GraphCast(DeepMind,GNN)
同代全球气象大模型的不同架构,参考其在分辨率、谱方法、图结构上的轻量与多尺度设计思路。
FengWu / FuXi / 风乌·伏羲(上海AI Lab / 复旦)
国产气象大模型,关注其在中期预报精度与效率上的工程取舍,可借鉴其 loss 加权与级联策略。
WeatherBench 2(评测基准)
RMSE / ACC 等气象预测指标的标准定义与评测口径参考,帮助理解 W 的计算逻辑。

压缩与加速工具(组委会已预装,优先用)

Torch-Pruning(VainF,DepGraph CVPR 2023)
结构化剪枝主力,自动处理层间依赖,直接降体积/显存/延迟。版本 1.6.1 已装。
TensorLy
张量分解(Tucker / CP / Tensor-Train),压缩线性层与卷积权重。版本 0.9.0 已装。
ONNX + onnxsim + onnxconverter-common
图导出、图简化(算子融合/常量折叠)、FP16 转换——阶段 1 拿分的核心三件套。

国产加速卡生态(部署落地)

海光 DCU 工具链:DTK / HIP / MIGraphX
DTK 为 DCU 软件栈,HIP 为编程模型,MIGraphX 为类 TensorRT 的图推理引擎(算子融合 + 自动调优)。比赛网站提供 HIP 规范与 DTK 使用说明,务必先读。
OneScience 0.3.0 + OneSkills(曙光 AI4S 平台)
比赛运行底座,所有优化须在其上复现;OneSkills 用于 Prompt/Skill 人机协同提效。

方法论(知识蒸馏 / 量化)

知识蒸馏:Hinton KD(输出蒸馏)、FitNets(特征蒸馏)
阶段 3 设计 student 的方法基础;结合气象先验做加权蒸馏。
PyTorch 量化(PTQ / QAT)
INT8 与混合精度量化标准流程,精度掉太多时切 QAT 回补。

七、取胜要点小结

容易丢分的坑

  • 基线没测准 → 所有比值全偏
  • 误改计时代码 / 不可改参数 → 判违规
  • 不可复现(环境、随机性)→ 自动化测试跑不出
  • 只追压缩率,精度塌方 → W 拉低拖垮总分
  • 第三方未标注 → 学术诚信问题

拉开差距的关键

  • FP16 + 图优化先稳吃 U/V 基础分
  • 剪枝/分解/量化组合而非单点
  • 蒸馏 student + 气象先验加权,精度持平甚至超基线
  • 针对 i,j,k,l,m 做 Pareto 调参选最优点
  • 显存专项优化单独抠那 20 分
  • 文档写透"设计逻辑 + 技术细节",决赛答辩讲得清
